# Documentation

Living documentation for Latent. Anything here is meant to be read by both
humans and Claude/Codex agents working in the repo.

| Folder                   | Contents                                                                       |
| ------------------------ | ------------------------------------------------------------------------------ |
| [`adr/`](./adr/)         | Architecture Decision Records — one file per decision, immutable once accepted |
| [`specs/`](./specs/)     | Product and design specifications                                              |
| [`plans/`](./plans/)     | Phase-scoped execution plans (cross-referenced from `ROADMAP.md`)              |
| [`reviews/`](./reviews/) | External review prompts and outputs (Codex, etc.)                              |
| [`qa/`](./qa/)           | Manual hardware release checklists                                             |

## Start Here

- [`onboarding.md`](./onboarding.md) — local setup, package boundaries, and
  hardware-report expectations
- [`use-cases.md`](./use-cases.md) — product workflows Latent is designed to
  support
- [`open-source-launch-checklist.md`](./open-source-launch-checklist.md) —
  repository and release checklist before a public announcement
- [`qa/hardware-test-plan.md`](./qa/hardware-test-plan.md) — manual camera
  stability checks

End-user legal pages such as privacy policy and terms can live alongside the
marketing site when it exists; repo-critical technical docs stay here.
